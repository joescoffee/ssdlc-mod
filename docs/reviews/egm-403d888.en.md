# EGM security review report: google/elephant-goldfish-model @ `403d888`

> **Reported upstream**: the Medium-severity F1–F5 were filed as [google/elephant-goldfish-model#261](https://github.com/google/elephant-goldfish-model/issues/261), and the Low/Info F6–F13 as [#262](https://github.com/google/elephant-goldfish-model/issues/262) (both 2026-11-01).

> Run with `/ssdlc:safe-bootstrap` (2026-11-01). Both reviewers had only Read/Grep/Glob, did not execute any code in the repo, and did not open links outside the repo.
> - **Elephant** (`ssdlc:design-reviewer`): has full context (design documents, conclusions of the previous audit) and performs threat modeling.
> - **Goldfish** (`ssdlc:security-reviewer`): has no context at all and looks only at the code itself.
> - **Merge**: items raised by both are rated high confidence; items raised by only one were verified by the main context re-reading the code.
> - Mechanical scan (`gate_scan.py`, covering 227 files): 0 hits for secrets and dangerous patterns.

## Conclusion

**`FIX-BEFORE-MERGE`: no Critical findings and no malicious content.** On Claude Code, EGM can safely be used to review your own or trusted repos.
**But do not run `/egm-bootstrap` on untrusted repos**, because of F1 and F2: it executes the formatter configured by the repo itself, and the orchestrator reads untrusted content while holding Bash/Write. In that case use `/ssdlc:safe-bootstrap` instead.

## Confirmed not to be issues
- No hooks, `.mcp.json` or commands; the packaging script rejects hooks and MCP (`tests/unit/test_packaging.py:235-264`).
- All 7 skills set `disable-model-invocation: true`. Test commands detected by bootstrap are only written into the README and are not executed.
- All workflows pin actions to commit SHAs, use `persist-credentials: false`, and minimize permissions. Although `pr-scope-advisory.yml` uses `pull_request_target`, it does not check out PR code and has no script injection.
- `scripts/pack_plugin.py` checks symlinks and `is_relative_to`, only creates zips and never extracts them, so there is no zip-slip. `prepare_release.py` does not call subprocess.
