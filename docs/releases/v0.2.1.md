## ssdlc v0.2.1

> Historical release, published after the fact. It is superseded by [v0.5.0](https://github.com/joescoffee/ssdlc-mod/releases/tag/v0.5.0). Use v0.5.0 for new installs.

This release applies the fixes from the v0.2.0 self-review: goldfish findings SR-1 to SR-22 and elephant findings T1 to T22 ([`docs/reviews/ssdlc-0.2.0-self-review.en.md`](https://github.com/joescoffee/ssdlc-mod/blob/main/docs/reviews/ssdlc-0.2.0-self-review.en.md)).

### Changes
- **One rule set for untrusted repositories** (`references/untrusted-repo.md`), and every skill now points to it:
  - git runs only on your own clones, with the full hardening flags;
  - dependency audits only parse files;
  - nothing is executed without a sandbox;
  - review happens on a copy without `.git`, `CLAUDE.md` or `.claude`;
  - reports are treated as data.
- **Scanner** (`scripts/gate_scan.py`):
  - `# ssdlc: allow` markers are ignored by default and apply only with `--honor-markers`. Even then they never hide secrets or hidden characters.
  - Every excerpt is redacted and has control characters escaped.
  - ReDoS protection: lines are capped at 4 KB and quantifiers are bounded.
  - Only regular files are opened, with `O_NOFOLLOW|O_NONBLOCK`. Missing, unreadable, special or oversized files are listed as skipped, and the scan exits with code 3 (INCOMPLETE).
  - New options `--files-from` (NUL-separated) and `--`.
  - New rule `repo.git-config-exec`, which flags executable `.git/config` keys.
  - MCP configs are parsed as JSONC. The scanner also recognises `npx.cmd` and `cmd /c`, and accepts only exact version pins.
- **Guard hook**:
  - Path checks are case-insensitive and work on normalised paths.
  - The credential deny-list covers more locations.
  - Recursive Grep/Glob from the filesystem root, home or system directories is refused.
  - The reviewer type is resolved through `$.agent.list()` and `$.plugin.name`.
- **Skills**:
  - They stop (fail closed) when no ssdlc reviewers are available.
  - Each claim is checked against evidence before acting on it.
  - PASS does not mean merge approval.
  - `vuln-fix` can only be started by you (`disable-model-invocation`), runs tests only in a sandbox, and may not weaken existing checks.
  - Reports are sanitised before they are saved, and the number of reviewers is capped.
- **Docs**: a known-limitations section, a disposition table for the self-review findings, and a time-scoped EGM review report.

### Verified
53 unit tests and 13 hook tests pass.

### Known limitations at this version
- The main session is not bounded by the guard. Review mode arrived in v0.3.0.
- Reviewer file access is a deny-list, not an allow-list. The allow-list arrived in v0.4.0.
- TOCTOU and hard links need an OS-level sandbox.

## 繁體中文

> 補發的歷史版本，已被 [v0.5.0](https://github.com/joescoffee/ssdlc-mod/releases/tag/v0.5.0) 取代，新安裝請使用 v0.5.0。

本版套用 v0.2.0 自我審查的修正：goldfish 發現 SR-1～SR-22、elephant 發現 T1～T22（[`docs/reviews/ssdlc-0.2.0-self-review.md`](https://github.com/joescoffee/ssdlc-mod/blob/main/docs/reviews/ssdlc-0.2.0-self-review.md)）。

### 變更
- **處理不受信任 repo 的單一規則**（`references/untrusted-repo.md`），所有技能都會引用：
  - git 只在自己的 clone 上執行，並加上完整強化參數；
  - 依賴稽核只解析檔案；
  - 沒有沙箱就不執行任何東西；
  - 只審查移除 `.git`、`CLAUDE.md`、`.claude` 的副本；
  - 報告一律視為資料。
- **掃描器**（`scripts/gate_scan.py`）：
  - `# ssdlc: allow` 標記預設不採用，只有加 `--honor-markers` 才生效；即使生效，也不能隱藏 secret 與隱形字元。
  - 每段摘錄都會遮蔽並跳脫控制字元。
  - 防 ReDoS：每行上限 4 KB，量詞有上限。
  - 只開啟一般檔案，使用 `O_NOFOLLOW|O_NONBLOCK`；找不到、無法讀取、特殊或過大的檔案列為 skipped，並以結束碼 3（INCOMPLETE）結束。
  - 新增 `--files-from`（以 NUL 分隔）與 `--` 參數。
  - 新增 `repo.git-config-exec` 規則，抓出 `.git/config` 中可執行的設定。
  - MCP 設定以 JSONC 解析；也能辨識 `npx.cmd`、`cmd /c`，且只接受精確版本鎖定。
- **守門 hook**：
  - 路徑比對不分大小寫，並先正規化。
  - 憑證黑名單涵蓋更多位置。
  - 拒絕從檔案系統根目錄、家目錄或系統目錄做遞迴 Grep/Glob。
  - 以 `$.agent.list()` 與 `$.plugin.name` 判斷審查員類型。
- **技能**：
  - 沒有可用的 ssdlc 審查員時就停止（fail closed）。
  - 先拿證據核對每項說法，再採取行動。
  - PASS 不等於核准合併。
  - `vuln-fix` 只能由使用者啟動（`disable-model-invocation`），只在沙箱中跑測試，且不得削弱既有檢查。
  - 報告存檔前會先清理，審查員數量有上限。
- **文件**：新增已知限制章節、自我審查發現的處置表，以及標明時間範圍的 EGM 審查報告。

### 驗證
53 個單元測試與 13 個 hook 測試全部通過。

### 此版本的已知限制
- 主 session 不受 guard 約束；審查模式在 v0.3.0 才加入。
- 審查員的檔案限制是黑名單，不是白名單；白名單在 v0.4.0 才加入。
- TOCTOU 與 hard link 需要作業系統層的沙箱。
